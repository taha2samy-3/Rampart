# 18 — Brand

A short guide so the product, the docs and the repository look like one thing.

## Positioning

Rampart is the open, Kubernetes-native place where a security team sees every finding from every scanner as one prioritized queue, because it explains each risk score and runs as ordinary cluster workloads instead of a separate appliance.

Personality: exact, calm, plain-spoken. It states what it knows and what it does not. It never dramatizes risk.

## The mark

![Rampart logo](images/logo.svg)

A flat-top hexagon split by a crenellation line into two interlocking pieces.

- The **hexagon** is the cloud-native container shape.
- The **lower piece** is a wall with three merlons: the rampart.
- The **interlock** is two sets of things meshing: findings from many tools brought together into one line of defence.

It is flat, uses two solid colours, has no gradient, outline or shadow, and keeps its silhouette in one colour.

| File | Use |
|---|---|
| [`images/logo.svg`](images/logo.svg) | Lockup on light backgrounds |
| [`images/logo-dark.svg`](images/logo-dark.svg) | Lockup on dark backgrounds |
| [`images/logo-mono.svg`](images/logo-mono.svg) | One colour, inherits `currentColor` |
| [`images/logo-mark.svg`](images/logo-mark.svg), [`logo-mark-dark.svg`](images/logo-mark-dark.svg), [`logo-mark-mono.svg`](images/logo-mark-mono.svg) | Mark alone: avatars, app icon |
| [`images/favicon.svg`](images/favicon.svg) | 16 to 32 px, wider gap between the pieces |

The wordmark is "rampart" in lower case, set in Red Hat Display ExtraBold and converted to outlines, so it renders the same everywhere and needs no font.

Rules:
- Clear space on every side equals the height of one merlon tooth (about a fifth of the mark's height).
- Minimum size: 16 px for the mark (use the favicon file), 96 px wide for the lockup.
- Do not recolour the two pieces independently, add effects, rotate, outline, or place the colour version on a busy or mid-tone background. Use the mono version there.
- The mark may stand alone once the name is established nearby.

Regenerate the files with `python3 docs/images/generate_logo.py docs/images` (needs `fonttools` and the Red Hat Display font).

|---|---|---|

| Rampart teal | `#19C3A6` | The upper piece. Resolved and reduced-risk states |
| Ink | `#1B2233` (wordmark `#0F172A`) | Text |
| Slate wash | `#F3F5F8` | Chrome surfaces |
| Rule | `#D5DAE3` | Dividers |
| Indigo on dark | `#8C98FF` | Mark and links on dark surfaces |
| Teal on dark | `#2DD4BF` | Mark on dark surfaces |

Risk colours (critical `#B4232A`, high `#D9622B`, medium `#C99A1A`, low `#6B7C93`) belong to the product interface, not to the brand. Brand colours are never used to signal severity.

## Typography

- Red Hat Display for the wordmark and page titles.
- Red Hat Text for interface and documentation body.
- Red Hat Mono for code, queries, paths and identifiers.
- Noto Sans Arabic for Arabic.

All are open-licensed (SIL OFL).

## Voice

- Say what happened and what to do next. "Parsing failed at line 2 104: unexpected end of file. Upload the report again."
- Name things the way an analyst does: "Detected by", "Due", "Known exploited".
- Sentence case. No exclamation marks. No fear language: "3 findings are overdue", not "Your systems are at risk".
- Numbers carry units and dates are absolute in exports, relative in the interface.

## Diagrams

Documentation diagrams are generated by [`images/generate.py`](images/generate.py) with one palette: teal for the write path, indigo for the read path, amber for the control plane, slate for state and external systems. Regenerate instead of editing the SVG files by hand.

## Status

The name "Rampart" and this identity are a proposal. Check trademark and package-name availability before the first public release.
